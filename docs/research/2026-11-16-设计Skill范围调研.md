# 设计 Skill 范围调研与优化建议

调研日期：2026-11-16。项目基线：`1bb81b5a4105884113ad08eba783e40b19b988b2`。

本轮完成了项目文档与代码审查、官方资料对照和三项脚本复现。尚未做不同设计类型的成图对照，以下范围建议是基于证据的方案判断，不代表已经证明新版本更好。

## 结论

建议从“只做 A4 产品手册”扩展到**静态平面设计**，首先做好海报、封面、宣传图等单页设计，并保留现有手册为独立的多页模式。系列图文和轻量信息图可以后续加入；摄影修图、插画、品牌标识、UI、三维和视频不在第一轮内一并承诺。

判断边界的依据应是：任务是否主要依赖**内容组织、视觉层级、字体、构图和传播尺寸**，而非最终文件是否恰好是一张图片。

扩大品类本身不必然降低质量。更实际的风险是不同任务被迫遵循同一流程、审美默认值被写成硬限制、加载不相关知识，以及新增能力没有成品验收。

## 现有项目具备什么

- 已有网格、字体、色彩、图像、留白与叙事知识，适合成为共享基础。
- 采用 Agent 做设计判断、HTML 母版、浏览器目检、PDF 交付，避开了完全硬编码的版式引擎。
- 入口、模板、页面 Schema 和转换脚本仍围绕 A4 竖版多页手册；目前不能仅修改 description 就声称支持一般图片设计。
- 风格有六个方向，但规则多偏向克制的杂志与机构宣传册。适合部分任务，不能代表所有设计任务的优选风格。

### 已复现的交付问题

| 检查 | 实际结果 | 影响 |
|---|---|---|
| HTML 引用不存在的图片，保留 `{{产品名}}`，配空图片清单 | `check.mjs` 返回 `pass: true` | 工具通过不能证明文件可交付 |
| 下载目录为 `downloads/`，清单写在上级目录 | 清单保存 `cover.png`，而实际文件为 `downloads/cover.png` | 相对清单路径找不到图片 |
| 示例 10 页 HTML 转 PPTX | 报告跳过第 2、3、6、8 页；实际压缩包只有 6 张幻灯片 | 可编辑输出不完整 |
| 检查该 PPTX 的文本 XML | 模块说明、行程条目和规格值丢失 | 即使页面保留，内容仍可能为空 |

另一个安装问题：仓库中的 lockfile 把依赖登记为普通依赖，`package.json` 中则是可选依赖；`pnpm install --frozen-lockfile` 因不一致失败。

结构自检通过（23 项），但它主要检查文件和关键字存在，因此没有发现以上行为问题。复现摘要见 [基线证据](evidence/2026-11-16-baseline.json)。

### 会妨碍扩展的规则

- 页数固定在 6／8／10 页；少量内容也被推向至少 6 页。
- 把渐变遮罩称为文字压图的唯一正确做法。
- 默认将品牌色压暗、限制强调色大面积使用，不适合所有品牌和活动宣传。
- 读者类型被直接映射成风格，同一产品换读者即要求风格不同，忽略既有品牌和用户提供的视觉参考。
- 小图、圆角、纯黑等被普遍视为负面信号，会排除部分合理的设计语言。

这些大多应降级为当前编辑风格的可选经验。内容准确、图片不变形、文字可读、裁切完整等才适合成为跨类型的验收要求。

## 外部资料带来的判断

### Skill 应围绕连贯的工作单元组织

Agent Skills 官方建议：太窄会导致同一任务反复加载多个 skill，太宽又会难以准确触发；较大的 skill 应按条件读取专门参考。

对本项目的推论：可以共用一个平面设计入口，但海报和手册应加载不同流程，不应把所有指导拼进同一份长文。来源：[Best practices for skill creators](https://agentskills.io/skill-creation/best-practices)。

### “设计概念 → 成图 → 精修”值得保留，单一审美不宜照搬

Anthropic 的 `canvas-design` 面向海报等静态视觉，先建立视觉理念，再输出 PNG／PDF，并要求复查精修。它本身偏艺术表达、少量文字，因此不能直接替代资料密集的产品宣传或手册流程。

对本项目的推论：借鉴清晰的设计意图和二次审视；具体艺术风格、文字占比和构图偏好仍由任务决定。来源：[canvas-design 原始 SKILL.md](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md)。

### 生图和精确排版应按任务组合

OpenAI 的图像生成文档仍列出精确文字位置、清晰度、跨图一致性和精密构图方面的限制。

对本项目的推论：氛围或插画优先的画面可以先用图像生成；长中文、价格、日期、Logo、参数或多页一致性要求较高时，优先保留可直接编辑与核对的排版层。无需强制每张图都拆层，但不能把“生成成功”当作“文案正确”。来源：[Image generation — Limitations](https://developers.openai.com/api/docs/guides/image-generation#limitations)。

### 单页、多页与多尺寸可以共用资产，仍需各自验收

Adobe Express 提供多页设计和独立的尺寸调整操作，说明这些工作可以共享一个设计环境。该产品事实并不能证明本项目已经具备相同能力。

对本项目的推论：可以统一品牌、素材和风格，再按输出类型处理分页、裁切和内容重排；修改宽高不能替代成品检查。来源：[多页设计](https://helpx.adobe.com/express/web/arrange-layers-and-pages/add-pages.html)、[调整页面尺寸](https://helpx.adobe.com/express/web/arrange-layers-and-pages/change-page-size.html)。

### 质量提升需要旧版对照

Agent Skills 官方评测指南建议用相同任务比较新旧版本或无 skill 基线，客观要求用程序检查，整体视觉质量结合盲评与人工检查。

对本项目的推论：不能靠补充术语、增加参考文件或一次自我打分来证明设计能力增强。来源：[Evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills)。

## 建议支持边界

| 任务 | 建议 | 专门要处理的内容 |
|---|---|---|
| 海报、封面、Banner、活动宣传图、邀请图 | 首批重点 | 主视觉、标题层级、传播动作、裁切与实际阅读尺寸 |
| 产品手册、宣传册、项目目录 | 保留并修复 | 分页、内容密度、全书一致性、PDF 与源文件完整性 |
| 轮播图、系列图文、长图 | 下一批 | 阅读顺序、段落拆分、跨图一致性与移动端阅读 |
| 轻量信息图 | 有真实需求后加入 | 信息关系、数据与标签准确性，不能只做装饰 |
| 商品摄影、人物修图、插画、场景合成 | 由图像工具完成素材或专门任务 | 产品／人物保真、局部修改边界、光影与图像质量 |
| Logo 与完整品牌识别系统 | 可协助探索，暂不承诺定稿 | 标志结构、缩放适用性、各类品牌应用规范 |
| UI、网站交互、三维、视频 | 第一轮不扩展 | 它们需要明显不同的制作与验收流程 |

公众号封面可以作为单页设计的一个传播场景，不必再单独维护一套通用设计知识；其平台裁切要求按实际任务核查。

## 结构建议

先保留仓库名，避免重命名和安装路径迁移成为优化的前置条件。范围确认后，才决定是否把 skill 名改为更准确的 `graphic-design`。

建议的逻辑结构，而非要求立刻建立所有文件：

```text
入口：理解用途、读者、必须保留的内容、尺寸与交付格式
  ├─ 单页：海报／封面／宣传图
  ├─ 多页：手册／目录
  └─ 系列：轮播／长图（后续）

共享：设计方向、字体与色彩、素材处理、质量复核
工具：按任务使用生图、原生设计工具或 HTML／SVG 排版
```

共享入口只决定本次任务需要什么，不统一限制为 A4、不强制所有图片先填产品 JSON，也不要求每次都生成多个方案。用户给了成熟方向或只改一个日期时，直接处理局部需求。

## 推荐实施次序

1. **修复现有交付链路。** 缺图、占位符、清单路径、PPTX 丢页丢内容，以及安装一致性；这些问题无论是否扩范围都应处理。
2. **整理共享原则。** 将 A4、页数、叙事弧和编辑风格专有规则留在手册模式；消除与品牌参考冲突的普遍化审美限制。
3. **只增加单页模式。** 覆盖海报、封面与宣传图；保留两种有效路径：图像表现优先，或精确排版优先。以交付要求选择，不锁死工具。
4. **完成三组对照，再决定下一次扩展。** 一张文字精确的宣传海报、一份现有产品手册、同一主题的跨尺寸改版。使用相同内容、资产和模型／工具条件，记录实际用时与修改次数。

三组对照的客观要求包括文字与数字、尺寸、文件可打开、无缺图与裁切溢出、多页内容完整。视觉评审比较信息层级、品牌匹配、构图、辨识度和成套一致性，不规定必须留白多少或必须采用哪种风格。

第一批若某类任务明显退步，就收回对应规则或拆分流程，暂缓新增模式。核心目标是可靠地交付设计，而不是让触发词覆盖所有图片需求。
