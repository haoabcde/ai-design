## 直接影响本轮实现的做法

1. **保留统一入口，按任务和制作路线读取专门流程。** 单页设计／产品手册各自处理内容组织，手册同时支持 HTML 与整页生图，不将所有图片任务塞进一套固定模板。
2. **把提示词、参考与成功页面当作可复用成果。** 多页项目保存每页完整提示词；以已选页面和原始产品图保持身份与风格，针对失败页面或局部问题修改。
3. **生图可以完成整页设计，精确内容仍需逐项核对。** 产品或品牌固定项与允许变化项分清；生成页面不自动等同于可编辑文字。
4. **HTML 路线可选生图参考。** 将生图当作构图探索，再用原始资料重建参数、文本和图表；不把这一做法强制施加到用户选择的整页生图路线。
5. **输出能力按实际文件验证。** PDF 核对页序、尺寸与清晰度；生图图片的实际像素和有效 ppi 单独记录；PPTX 的可编辑性不由“导出成功”推断。

没有新增另一套生图供应商接入、应用画板、固定批量数、视频流程或默认多轮确认。上述模式用于改进当前两条路线，未复制第三方源码。

## 主分支合并后的具体吸收

PR #1 合并后，再次读取 baoyu 系列图片 SKILL 的提示词与首图参考部分，以及 Creative Production 的素材保留说明；文件 blob 与上表记录相同。

本项目新增的可选 `booklet.json` 把页序、共同简报、逐页提示词、参考角色和目检状态连接到 PDF 合页，并保留直接传图片的简单用法。这是对可复用成果、页面续作和素材固定项管理的自主实现，没有复制第三方脚本或引入其整套运行环境。

已用 8 项 Python 测试和现有两页样册验证：未检查页面不能进入清单导出；缺失提示词或参考文件会报告错误；从其他工作目录导出时页序、标题和源图像素保持正确。不同页有意复用图片仍被保留为独立页。
