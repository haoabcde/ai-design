# 从内容形成视觉方向

用于开放式创作、建立新的视觉体系，或处理“太普通／没有设计感”等反馈。已有成熟品牌和清楚参考时沿用它们，局部改字不重开整套探索。

## 找到可见的概念

先判断这次缺的是内容、组织还是视觉表达。读者需要的事实和关系尚未建立时，先编辑资料；不要用更多材质、意象或装饰补空缺。再从信息关系、文字、形态、动作、材料或体验中寻找有表达力的线索，推到构图。例如路线的城市切换、折叠结构的部件关系、舞台的聚光，都可以形成不同的视觉概念。

用很短的说明落实四件事，通常可以直接记录在提示词或源文件中：

- **核心表达**：读者先理解或记住什么，哪部分内容支持它？
- **字图关系**：文字是主角、图像的框、与主体交错，还是为一个强主视觉让位？
- **形式语言**：选择什么字体气质、对比、材质与节奏，它们为何适合本次内容？
- **延续方式**：这个概念如何进入内页或另一个尺寸，而不只是一张封面装饰？

“海报感、杂志风、高级、克制、极简”可以描述方向，但不能替代这些决定。也不必每次交付一份设计宣言。

## 用画面试，而不只写风格名

方向未定时做少量可比较的视觉原型。候选在主视觉材料、构图逻辑或排字角色上应有实质区别；只换配色、换照片或换圆角不足以测试方向。保持相同主题和关键内容，避免靠删信息赢得更空的画面。

可直接用生图完成概念画面，或在 HTML／原生工具中做关键页。要原创插画、摄影或拼贴时使用相应图像工具，简单信息图与原生几何排版则可用代码。尊重用户已指定的全生图或可编辑路线；未指定时按表达与修改需求选择，不自行限制为只有代码或只有生图。

手册优先试一张有代表性的封面和一张真实内容内页；两者能形成同一视觉语言后再扩展。无需固定候选数量或新增用户批准步骤；可以由 Agent 判断并推进，用户给出方向时及时调整。

## 看成品，找到下一次修改

把候选缩小并排看，再放大检查。以以下问题定位具体差距，而不是凑自评分数：

| 问题 | 如何采取行动 |
|---|---|
| 看起来丰富，却说不出读者得到什么？ | 回到本页任务，补足或重组关键内容；减少占用阅读空间却无助于表达的元素。 |
| 第一眼什么都差不多重要？ | 改变尺度、位置或对比，让一个明确入口成立，再安排阅读路径。 |
| 遮住名称后，它也能属于任何项目？ | 找回内容特有的形态或视觉材料，让它参与主体构图。名称可识别、强品牌复用等任务不必刻意追求新奇。 |
| 图只是在文字上下占一块位置？ | 检查裁切、视线、轮廓与文字的关系；图文相邻也可以成立，但应有清楚的视觉原因。 |
| 有一个漂亮封面，内页却退回通用列表？ | 把概念延续为导航、信息图、图片取景或页面节奏，而非每页贴同一张背景。 |
| 视觉语言依靠一堆装饰或大量小字？ | 保住最有效的一处关系，重组必要信息；去掉无作用的符号，保持正文可读。 |

选择最影响成品的一两处问题进行修改，再看实际画面。概念本身不成立时，改变构图或材料；局部精修不能补救错误方向。安静、重复、对称、留白和强色块都可以是有效选择，不把个人偏好写成普遍禁令。

## 如何处理用户否定

把“没有设计感”视为当前审美方向未获得认可。保留已确认的事实和阅读要求，重新比较概念、构图与参考；不要用测试通过、字号达标或“遵守设计原则”来反驳，也不要擅自解释为用户一定喜欢复杂装饰。

有参考作品时，分析它的尺度关系、图像语言与版面节奏，再原创转译；没有参考时先拿出实际候选。可请求用户针对画面选择或指出偏好，但不把提供参考图变成继续工作的前提。

保存关键原型与选择理由，便于下一轮对照。展示作品和实际修改，明确哪些结论来自用户、哪些是 Agent 的选择；不宣称一个示例或自评已经证明 skill 普遍具备优秀审美。

实际例子见 [水岸江苏的设计演进](../examples/jiangsu-waterways/design/directions.html)：同一份路线试做封面与行程页后，用户认可“水线版画”，认为“巨型竖排字＋窄幅园林照片”的另一方案老土，后者已退出当前展示。

用户后来认可 HTML 日光版，但认为全生图手册过于华丽、内容与设计不足。因此这些画面只保留为探索记录，不能作为后续默认答案。回到具体任务检验表达，避免把某次认可的配色、插画、母题或构图推广到所有页面。
