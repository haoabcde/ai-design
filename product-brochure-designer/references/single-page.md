# 单页设计

适用：海报、封面、宣传图、Banner、邀请图，以及同一内容的跨尺寸改版。

## 从观看情境确定层级

- 海报常需远看识别主题、近看读细节；封面常在小缩略图中被看到；宣传图还要让产品和行动信息清楚。
- 先划分主信息、辅助信息、必要细则。视觉焦点服务主信息，不能让所有文字同样突出。
- 尺寸取自用户或实际发布要求。用户未指定时可用适合用途的比例并说明假设，例如移动端海报 3:4、通用横版封面 16:9；这些不是特定平台的官方规范。
- 中文与长英文标题都应实际换行检查。不要为了迁就主视觉而随意删改必须保留的文案。

## 选择制作路径

生图是正式设计路线：可以让模型完成整张海报的构图、文字、图像与视觉语言，不必默认只生成背景。先读 `image-generation.md`，把准确文案、阅读顺序、品牌与尺寸交给模型，并核对最终文件。信息、品牌与修改准确性要求较高时，可以保留独立排版层；这是根据任务选择的实现方式，不是所有生图任务的前置条件。

已有参考图时，先区分它是编辑目标、风格参考还是需要插入的素材。参考作品的字体、布局关系可以启发设计，不照搬别人的标识或内容。已有成品只改日期或一句文字时，优先改源文件或定点编辑，保留其余元素。

## HTML 路线

`templates/graphic.html` 是固定像素画布的机制示例，默认 1080×1440。复制后替换文案与设计，不必沿用其构图。改尺寸时同步修改画布 CSS 和相应打印尺寸；以浏览器实际测得的页面宽高为准。

- 一个 `<section class="page page-graphic">` 对应一张图。
- 图像放本地，用正确的 `object-fit` 与焦点位置；Logo 通常用 `contain` 或原比例，摄影裁切才常用 `cover`。
- 用宿主浏览器工具截取**画布元素本身**，排除浏览器界面、预览背景和页外留白。屏幕像素与输出像素可能因设备倍率不同，交付前读实际 PNG 尺寸。
- 等待字体加载与图片解码，再截图；检查所用字体是否确实存在。需要跨机器复现时提供有许可的本地字体或记录回退。
- 最终 HTML 先运行 `check.mjs`。该脚本不测量布局、字体或 PNG 尺寸。

生图／原生设计工具路线不必为了检查器再生成一份 HTML；直接核对其实际导出结果。

## 改尺寸时重新设计关系

竖版转横版通常需要调整主视觉裁切、标题换行和信息分组。保留设计意图与品牌识别，分别检查新画幅的安全区、主体和阅读顺序，不把原图拉伸或随意裁掉信息。

## 验收

- 文案、数字、Logo 与输入一致；没有生成出的额外文字或伪数据。
- 第一眼看到的内容符合传播目标，小尺寸下主题仍清楚。
- 字体、颜色、图像与风格参考协调；不同方向有实质区别。
- 无溢出、缺图、不可读文字；主体和重要元素没被错误裁切。
- PNG 尺寸正确；透明背景、PDF 或源文件在用户需要时实际提供。

`examples/open-studio/` 提供同一虚构活动的竖版与横版排版示例，仅演示层级和改版，不代表所有任务应采用这种风格。
